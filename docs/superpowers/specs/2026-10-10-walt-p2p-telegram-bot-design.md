# Telegram-бот мониторинга Walt P2P

## 1. Цель

Создать и развернуть на сервере Telegram-бота, который отслеживает P2P-объявления Walt для `USDT/RUB` и `TON/RUB`, показывает лучшие цены покупки и продажи и присылает настраиваемые уведомления. Первая версия не совершает сделки.

## 2. Границы версии

Входит в версию 1.0:

- получение активных объявлений Walt P2P по API;
- пары `USDT/RUB` и `TON/RUB`;
- ручная сводка текущих цен;
- уведомления по ценовому порогу;
- уведомления по процентному изменению;
- регулярные сводки;
- хранение настроек и состояния между перезапусками;
- развертывание как `systemd`-службы.

Не входит:

- автоматическое совершение сделок;
- пополнение или вывод средств;
- доступ к балансу кошелька;
- веб-панель или отдельное мобильное приложение.

## 3. Источник данных

Бот использует Walt P2P Integration API 1.0.0:

- `POST https://p2p.walletbot.me/p2p/integration-api/v1/item/online`;
- ключ передается в заголовке `X-API-Key`;
- `fiatCurrency` всегда равен `RUB`;
- запросы выполняются для `USDT` и `TON`, для сторон `BUY` и `SELL`;
- интервал опроса — 30 секунд, что соответствует заявленной частоте обновления данных Walt.

Для покупки криптовалюты бот выбирает минимальную цену из онлайн-объявлений продавцов. Для продажи — максимальную цену из онлайн-объявлений покупателей. В сводку входят цена, лимиты, методы оплаты, никнейм и рейтинг мейкера.

## 4. Telegram-интерфейс

- `/start` — первичная настройка и показ главного меню.
- `/price` — текущие лучшие цены по обеим парам.
- `/alert` — пошаговое создание ценового порога: монета, направление, условие «выше/ниже», цена.
- `/change` — пошаговое создание правила процентного изменения.
- `/schedule` — выбор интервала или ежедневного времени сводки.
- `/alerts` — список активных правил.
- `/delete` — выбор и удаление правила.
- `/pause` и `/resume` — приостановка и возобновление рассылки.
- `/help` — справка.

Для пошаговых действий используются inline-кнопки. Ввод цены, процента и времени валидируется; некорректный ввод не создает правило.

## 5. Механика уведомлений

### 5.1. Ценовой порог

Правило срабатывает при переходе цены через заданную границу. После отправки оно не повторяется, пока цена не вернется на исходную сторону порога. Это устраняет повторы на каждом цикле опроса.

### 5.2. Процентное изменение

При создании правила текущая цена становится базовой. Когда абсолютное изменение достигает заданного процента, бот отправляет уведомление с направлением движения. Отправленная цена становится новой базой.

### 5.3. Сводки

Поддерживаются:

- интервальные сводки через целое число часов;
- ежедневная сводка в заданное время по часовому поясу `Asia/Yekaterinburg`.

Каждая сводка содержит цены покупки и продажи для `USDT` и `TON`.

## 6. Компоненты

- **Telegram-приложение** — команды, inline-кнопки, FSM-сценарии и форматирование сообщений.
- **Walt API client** — авторизованные HTTP-запросы, таймауты, ограниченные повторы и преобразование ответа в доменные модели.
- **Market service** — выбор лучших объявлений и подготовка сводки.
- **Alert engine** — оценка порогов, процентных изменений и сроков сводок.
- **Repository** — асинхронное хранение в SQLite с явными миграциями схемы.
- **Monitor loop** — один цикл опроса Walt, который обслуживает все правила без дублирования API-запросов для каждого пользователя.

## 7. Данные

SQLite хранит:

- единственный Telegram ID владельца;
- статус паузы;
- правила ценовых порогов;
- правила процентных изменений;
- расписания;
- последние базовые цены и состояние перевооружения порогов;
- время последней отправки сводки.

Токен Telegram, ключ Walt API и другие секреты не хранятся в SQLite.

## 8. Доступ и безопасность

- Первый Telegram-аккаунт, отправивший `/start` при отсутствии владельца, атомарно записывается как владелец.
- После записи владельца все апдейты от других Telegram ID отклоняются.
- До первого запуска службы владелец может быть задан через `OWNER_TELEGRAM_ID`; этот способ имеет приоритет и исключает захват бота посторонним аккаунтом.
- Секреты хранятся в серверном `.env` с правами `0600` и не попадают в Git.
- Журналы не содержат токены, API-ключи, пароли или HTTP-заголовки авторизации.

## 9. Ошибки и устойчивость

- Каждый HTTP-запрос имеет таймаут.
- Временные ошибки, `429`, `503` и сетевые сбои повторяются с ограниченной экспоненциальной задержкой.
- Невалидный ключ (`401`/`403`) не повторяется в быстром цикле и фиксируется как операционная ошибка без значения ключа.
- Отсутствие объявлений не трактуется как нулевая цена и не запускает правила.
- Один и тот же сбой не порождает повторяющиеся Telegram-сообщения.
- Неудачная отправка уведомления не отмечает правило как отпработанное.

## 10. Тестирование

Автоматические тесты должны покрывать:

- разбор ответа Walt;
- выбор минимальной цены для покупки и максимальной для продажи;
- фильтрацию невалидных и неактивных объявлений;
- первое и повторное пересечение ценового порога;
- расчет положительного и отрицательного процентного изменения;
- замену базовой цены только после успешной отправки;
- сроки интервальных и ежедневных сводок в `Asia/Yekaterinburg`;
- атомарное закрепление первого владельца;
- отказ в доступе другим Telegram ID;
- сохранение правил после перезапуска;
- реакцию на таймауты, `429`, `503`, пустые списки и невалидные ответы.

Интеграционная проверка перед развертыванием выполняет реальный запрос к Walt для всех четырех сочетаний монеты и стороны. После развертывания проверяются Telegram-команды, персистентность после перезапуска и состояние `systemd`-службы.

## 11. Развертывание

- Python 3.12 и виртуальное окружение.
- Отдельный системный пользователь без shell-доступа.
- Каталог приложения в `/opt/walt-price-bot` и каталог данных в `/var/lib/walt-price-bot`.
- Секреты в отдельном `/etc/walt-price-bot.env` с правами `0600`.
- `systemd`-служба с автозапуском, ограниченными повторами и защитными параметрами.
- Журналы читаются через `journalctl`.

## 12. Критерии готовности

Работа считается завершенной, когда:

1. Все автоматические тесты проходят.
2. Реальные запросы Walt возвращают объявления `USDT/RUB` и `TON/RUB` для обеих сторон.
3. `/price` возвращает корректно отформатированную сводку.
4. Все три типа уведомлений создаются, срабатывают по заданным правилам и не создают дубликаты.
5. Другой Telegram ID не получает доступа к функциям бота.
6. После перезапуска службы настройки и активные правила сохраняются.
7. `systemctl is-active walt-price-bot` возвращает `active`, а в журнале нет секретов или необработанных ошибок.
